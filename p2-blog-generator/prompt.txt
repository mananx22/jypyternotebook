================================================================================
PROJECT: p2-blog-generator — AI Blog Generation API
================================================================================

A FastAPI-based REST API that uses LangGraph and Groq LLM (LLaMA 3.1 8B) to
automatically generate blog posts (title + content) from a given topic, with
optional translation to Hindi or French via a conditional routing workflow.

================================================================================
HIGH-LEVEL WORKFLOW
================================================================================

1. Client sends a POST request to /blogs with JSON body:
   {"topic": "...", "language": "..."}
2. The API initializes a Groq LLM connection.
3. A LangGraph StateGraph is built based on the use case:
     • "language" use case (currently active):
         Nodes: title_creation → content_generation → route → (hindi_translation | french_translation)
         Uses conditional edges to select the translation node based on language.
     • "topic" use case (currently commented out in app.py):
         Nodes: title creation → content_generation
         Simple sequential flow without translation.
4. The graph is compiled and invoked with the initial state.
5. The final state (containing topic, blog, and current_language) is returned as JSON.

Execution flow (language use case):
  Client POST /blogs  →  app.py (FastAPI route)
                       →  Groqllm.get_llm() initializes ChatGroq
                       →  Graphbuilder.setup_graph("language") builds & compiles the graph
                       →  BlogNode.title_creation() generates the title
                       →  BlogNode.content_gen() generates the body
                       →  BlogNode.route() passes through current_language
                       →  BlogNode.route_decision() selects "hindi" or "french"
                       →  BlogNode.translation() translates content via structured output
                       →  Final BlogState returned to client

================================================================================
FILE-BY-FILE BREAKDOWN
================================================================================

--- app.py (Root) -------------------------------------------------------------
Entry point for the FastAPI web server. Defines API routes.

  • Imports & Setup:
      - Loads environment variables from .env via python-dotenv.
      - Creates a FastAPI app instance.
      - Sets the LANGSMITH_API_KEY environment variable from LANGCHAIN_API_KEY
        (used for LangSmith tracing/monitoring).

  • POST /blogs — create_blogs(request):
      1. Parses the incoming JSON body and extracts "topic" and "language" fields.
      2. Creates a Groqllm instance and calls get_llm() to get a ChatGroq object.
      3. Creates a Graphbuilder with the LLM.
      4. If both topic and language are provided:
           - Calls setup_graph(usecase="language") to build & compile the language graph.
           - Invokes the graph with {"topic": topic, "current_language": language.lower()}.
      5. (Commented out) If only topic is provided:
           - Would call setup_graph(usecase="topic") for topic-only generation.
      6. Returns the final state as {"data": state}.

  • Note: Server runs via uvicorn on 0.0.0.0:8000 with hot-reload when run directly.

--- main.py (Root) -----------------------------------------------------------
A simple placeholder entry point. Prints a greeting when run directly.
Not used in the API workflow.

--- langgraph.json (Root) ----------------------------------------------------
LangGraph Studio / API configuration file.
  • "dependencies": ["."] — project root as dependency.
  • "graphs": maps "graph_generator" to ./src/graphs/graph_builder.py:graph
    (the module-level compiled graph instance).
  • "env": "./.env" — points to the environment file.

================================================================================
src/ MODULES
================================================================================

--- src/__init__.py -----------------------------------------------------------
Marks the src/ directory as a Python package.

--- src/llms/groqllm.py ------------------------------------------------------
Wrapper around the Groq LLM API using langchain-groq.

  class Groqllm:
    • __init__():
        - Calls load_dotenv() to load environment variables from a .env file.

    • get_llm():
        - Reads the GROQ_API_KEY from environment variables.
        - Sets it in os.environ for the Groq SDK to use.
        - Creates and returns a ChatGroq instance using:
            • model: "llama-3.1-8b-instant" (fast, lightweight LLaMA variant)
            • api_key: wrapped in Pydantic's SecretStr for secure handling
        - Raises a ValueError if initialization fails.

--- src/states/blogstate.py --------------------------------------------------
Defines the data models (state schema) used throughout the graph.

  class Blog (BaseModel):
    • title (str): The generated blog title (Field with description).
    • content (str): The generated blog body text (Field with description).

  class BlogState (TypedDict):
    • topic (str): The input topic provided by the user.
    • blog (Blog): A Blog object holding the title and content.
    • current_language (str): The target language for translation (e.g. "hindi", "french").

--- src/nodes/blog_node.py ---------------------------------------------------
Contains the actual processing logic for each step in the blog generation
pipeline. Each method receives the current BlogState, calls the LLM, and
returns a partial state update that LangGraph merges into the shared state.

  class BlogNode:
    • __init__(llm):
        - Stores the LLM instance for use by all node methods.

    • title_creation(state: BlogState) -> dict:
        - Validates that state["topic"] exists and is non-empty.
        - Constructs a prompt asking the LLM (acting as an expert news reporter)
          to generate a creative blog title (max 10 words) for the given topic.
          Uses markdown formatting.
        - Calls llm.invoke(prompt) and extracts response.content.
        - Returns {"blog": {"title": "<generated title>"}}.
          LangGraph merges this into the shared state.

    • content_gen(state: BlogState) -> dict:
        - Constructs a prompt asking the LLM (acting as an expert blog writer)
          to generate a detailed ~70-line blog post for the given topic.
          Uses markdown formatting.
        - Calls llm.invoke(prompt) and extracts response.content.
        - Returns {"blog": {"title": state["blog"]["title"], "content": "<generated content>"}}.
          This preserves the title from the previous node and adds the content.

    • translation(state: BlogState) -> dict:
        - Constructs a prompt asking the LLM (acting as an expert linguist of
          the target language) to translate both the topic and blog content to
          the specified current_language, preserving format and tone.
        - Sends the prompt as a HumanMessage list.
        - Uses llm.with_structured_output(Blog).invoke(message) to get a
          structured Blog object back from the LLM.
        - Returns {"blog": {"content": translation_content}}.
          Note: Returns the full Blog object inside the content field.

    • route(state: BlogState) -> dict:
        - A pass-through node that simply returns {"current_language": state["current_language"]}.
        - Used as the source node for the conditional edge in build_language_graph().

    • route_decision(state: BlogState) -> str:
        - The routing function for conditional edges.
        - Returns "hindi" if current_language is "hindi".
        - Returns "french" if current_language is "french".
        - Otherwise returns the raw current_language value.

--- src/graphs/graph_builder.py ----------------------------------------------
Constructs and configures the LangGraph StateGraph that orchestrates the
blog generation workflow. Includes detailed inline comments (the separate
graph_builder_commented.py file has been merged into this file).

  class Graphbuilder:
    • __init__(llm):
        - Stores the LLM instance.
        - Creates a new StateGraph with BlogState as the state schema.

    • build_topic_graph() -> StateGraph:
        1. Creates a BlogNode instance with the stored LLM.
        2. Adds two nodes to the graph:
             "title creation"     → BlogNode.title_creation
             "content_generation" → BlogNode.content_gen
        3. Adds three edges defining the execution order:
             START → "title creation"
             "title creation" → "content_generation"
             "content_generation" → END
        4. Returns the configured StateGraph (not compiled).

    • build_language_graph() -> StateGraph:
        1. Creates a BlogNode instance with the stored LLM.
        2. Adds five nodes to the graph:
             "title_creation"      → BlogNode.title_creation
             "content_generation"  → BlogNode.content_gen
             "hindi_translation"   → Lambda wrapping BlogNode.translation with language="hindi"
             "french_translation"  → Lambda wrapping BlogNode.translation with language="french"
             "route"               → BlogNode.route
        3. Adds sequential edges:
             START → "title_creation"
             "title_creation" → "content_generation"
             "content_generation" → "route"
        4. Adds a conditional edge from "route":
             Uses BlogNode.route_decision as the routing function.
             Maps: "hindi" → "hindi_translation", "french" → "french_translation"
        5. Adds terminal edges:
             "hindi_translation" → END
             "french_translation" → END
        6. Returns the configured StateGraph (not compiled).

    • setup_graph(usecase) -> CompiledGraph:
        - Dispatcher that selects the graph to build based on the usecase string.
        - If usecase == "topic", calls build_topic_graph().
        - If usecase == "language", calls build_language_graph().
        - Compiles and returns self.graph.compile() for either case.

  Module-level code (for LangGraph Studio):
    - Creates a Groqllm instance and gets the LLM.
    - Builds and compiles the topic graph as a module-level `graph` variable.
    - This allows LangGraph Studio to discover and run the graph via langgraph.json.

================================================================================
DATA FLOW THROUGH THE GRAPH (language use case)
================================================================================

  Initial state:    {"topic": "AI in healthcare", "blog": ..., "current_language": "hindi"}
        │
        ▼
  ┌─────────────────────┐
  │  "title_creation"   │  BlogNode.title_creation()
  │  Input:  topic      │  → Calls LLM with title-generation prompt
  │  Output: blog.title │  → Returns {"blog": {"title": "..."}}
  └─────────┬───────────┘
            │
            ▼
  ┌──────────────────────────┐
  │  "content_generation"    │  BlogNode.content_gen()
  │  Input:  topic, title    │  → Calls LLM with content-generation prompt
  │  Output: blog.content    │  → Returns {"blog": {"title": "...", "content": "..."}}
  └─────────┬────────────────┘
            │
            ▼
  ┌──────────────────────────┐
  │  "route"                 │  BlogNode.route()
  │  Input:  current_language│  → Pass-through, returns {"current_language": "..."}
  └─────────┬────────────────┘
            │
            ▼  (conditional edge via route_decision)
     ┌──────┴──────┐
     │             │
     ▼             ▼
  ┌──────────┐  ┌──────────┐
  │  hindi   │  │  french  │  BlogNode.translation()
  │  transl. │  │  transl. │  → Calls LLM with structured output (Blog)
  │          │  │          │  → Returns {"blog": {"content": <Blog>}}
  └────┬─────┘  └────┬─────┘
       │              │
       ▼              ▼
      END            END

  Final state: {"topic": "AI in healthcare",
                "blog": {"content": <translated Blog object>},
                "current_language": "hindi"}

================================================================================
KNOWN ISSUES
================================================================================

  1. Groqllm.get_llm() has a string formatting bug: the except block uses
     "Error occured : {e}" (plain string) instead of f"Error occured : {e}"
     (f-string). The exception details will not be interpolated.

  2. content_gen() in blog_node.py accesses state["blog"]["title"] directly,
     which will fail if title_creation didn't run or returned None.

  3. translation() returns {"blog": {"content": translation_content}} where
     translation_content is a Blog Pydantic object (from structured output),
     not a raw string. This nests a Blog object inside the content field,
     which may cause serialization/type issues downstream.

  4. The french_translation lambda in build_language_graph() has a typo:
     "current_lanugage" (misspelled) instead of "current_language". This means
     the french translation node will not receive the correct language key.

  5. route_decision() only handles "hindi" and "french" explicitly. Any other
     language value is returned as-is, but there is no matching node in the
     conditional edge map, which will cause a LangGraph routing error.

  6. The topic-only code path in app.py is commented out, so the API currently
     only works when both topic AND language are provided.

  7. The title_creation node is named "title creation" (with a space) in
     build_topic_graph() but "title_creation" (with an underscore) in
     build_language_graph(). This inconsistency doesn't cause a runtime error
     but may be confusing.
